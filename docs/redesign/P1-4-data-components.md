# P1-4: Data components

Recorded 13 October 2026. Ticket P1-4 of the Murzak POS redesign (Done when: shown on the component page with sample data; AC-04 passes for these components).

## What was built

All of these live in `src/newlook/components/`, next to the P1-3 components, built only from the design tokens. A list page is now configuration: give it columns, rows and filters and the components build the layout. They exist only inside the New look, so nothing changes with the switch off.

| Component | What it is | States shown on the component page |
|---|---|---|
| **Table** | Header in label style (11.5px, 700, capitals), 12px cell padding, sticky header, row hover and selected-row fill, money right-aligned and written as KES. A row opens by click, Enter or Space; Arrow Up and Down move between rows | Data, loading, empty (names the next action), error (Try again), open row |
| **Summary row** | Up to three numbers above the list (label, value, optional note). A missing number is a dash | Data, loading |
| **Pagination** | "Showing 20 of 120" on the left; rows per page, "Page 2 of 6", Previous and Next on the right. Rows per page is 20 by default and can never be blank | First page, middle, last page, a strange size (falls back to 20), hidden when there are no rows |
| **Filter row** | Period presets (Today, 7 days, 30 days, Custom), a search box and up to two dropdowns. "Clear filters" appears only when a filter is set. Custom shows two day-first date fields and warns when the end is before the start | Default, custom period, filters set |
| **Tabs** | Each tab is a real link, so a link, a refresh or the Back button opens the same tab. Selected tab: brand-text, 2px underline, 600 weight, optional count chip. Arrow keys open the next tab | Selected, others, with count |
| **Segmented control** | Short exclusive choice. Selected: soft fill, brand-text, 600 weight. Arrow keys move and choose | Each choice selected, small size |
| **Detail panel** | Right-hand card, 4 of 12 columns beside the list and a full page below 1100px. Short id and status, key facts, one primary and up to three secondary actions, system references under a closed "Details" fold-out, Close, Previous and Next | Open, first and last row, loading |
| **Empty state** | Icon, plain headline, one sentence, one primary action | Empty, error |
| **Skeleton** | Grey shapes where content will be. Shown only after 200 ms of loading, space reserved so the page does not jump, shimmer stops for reduced motion | Loading |
| **List hook** (`useListParams`) | Keeps page, rows per page, search, period, custom dates and filters in the web address | Used by the sample page |

**The sample page.** The component page now has a working list page with 135 made-up sales (generated by a fixed formula; no shop data is used). Choose a row and its panel opens; change the tab, period, search, filters, page or rows per page and the address changes with it, so a refresh or a copied link opens the same view. A small "Show the list as" switch shows the loading, empty and error states.

## How the Spec's rules were applied

- **Filters live in the address**, including the page and the rows per page; a value equal to its default is left out so links stay short. Changing any filter returns to page 1. The open row is also in the address but is not counted as a filter, so "Clear filters" leaves it alone.
- **Rows per page is never blank.** Anything other than 10, 20, 50 or 100 (including an empty value) becomes 20.
- **The detail panel keeps the list position.** The list is beside the panel, so choosing a row never moves it. Below 1100px the list waits behind the panel and the page returns to the same scroll position when the panel is closed. Opening the panel moves the keyboard focus to its title; closing it returns the focus to the row that opened it; Escape closes it.
- **Colour is never the only signal.** The open row has the selected-row fill, a bar on its left edge and `aria-current`. Every status is an icon and a word. Errors say what went wrong in words.
- **Focus** is the 2px brand-text ring with a 2px offset on every new keyboard target (a row's ring is drawn just inside the row, because the table clips its corners).
- **Small screens:** below 768px segments, tabs, rows-per-page, Previous and Next are at least 44px. The presets share the full width so all four fit.
- **A table wider than its space** (many columns, or the panel open beside it) scrolls sideways instead of losing its right-hand columns, and a keyboard user can reach it. While it fits, the header stays stuck to the top of the page.
- **Reduced motion:** the skeleton shimmer stops.
- **No new colours or sizes.** Hover is the 8% ink overlay, pressed 16%, as in P1-3. A test fails if a colour is written in the new stylesheet.

These were needed by P1-4 and are limited to what it required: **Field** gained an optional leading icon (the search box); **Select** gained a 32px size and an inline label (rows per page; its menu opens upward because it sits at the foot of a list); **Button** gained an option to put the icon after the label (the Next button); **Icon** gained search, inbox, chevronLeft and chevronRight. ## Decisions and judgement calls (please read)

1. **Row height.** The Spec fixes the row padding at 12px but not the row height. Every row is 57px: 12px above and below the 32px row menu button added in P1-5, plus the 1px line (it was 49px, set by a 24px payment chip, before the menu existed). The loading rows use the same height so the page does not jump.
2. **"Showing x of y".** x is the number of rows on the screen and y the total with the filters applied, as in the Spec's "Showing 20 of 135".
3. **Period filtering in the sample page** works on made-up "days ago" values only. The real period filter is built with each list screen (Sales, P3-8, and so on) against the back end.
4. **The selected tab keeps only its own address.** In the sample page choosing a tab starts a fresh view (filters are cleared). Each real page decides how a tab and its filters combine; I have not guessed, and this is the Spec's silence, not a rule.
5. **No sorting by clicking a column header.** The Spec says "newest first" and does not ask for sorting, so none was built.
6. **Row action menu (the three dots)** arrives with the Menu in ticket P1-5.
